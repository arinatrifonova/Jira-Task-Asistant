main.py:
aiogram - отвечает за взаимодействие с Telegram
- Принимает сообщения пользователей.
- Распознаёт команды /start и другие
- Передаёт сообщения нужным обработчикам.
- Отправляет пользователям ответы.
- Обрабатывает нажатия на inline-кнопки.
- Поддерживает FSM (механизм хранения состояния диалога, например при создании задачи)

Dispatcher — это центральный обработчик событий в aiogram. Чтобы бот понимал, какую функцию нужно
запустить для каждой команды.
Создается объект диспетчера: dp = Dispatcher(storage=MemoryStorage())
Он получает события от Telegram и определяет, какой обработчик должен на них отреагировать.
Условно: Если пользователь отправил команду /start, вызови функцию start():
    @dp.message(CommandStart())
    async def start(message: Message):
        await message.answer("Привет!")

здесь: dp = Dispatcher(storage=MemoryStorage()) - указываем, где хранить состояния пользователей (как называется задача т тд)
aiogram использует FSM (Finite State Machine — конечный автомат), чтобы понимать, на каком шаге находится пользователь
MemoryStorage() хранит эти состояния в оперативной памяти.

+ также мы импортируем маршрутизатор(router) из handlers.py и подключаем его к диспетчеру

Telegram (пользователь отправляет команду) -> Dispatcher (Получает событие и ищет подходящий обработчик) ->
-> Router (Содержит обработчики из handlers.py) -> Нужная функция в handlers.py

users.db:
для хранения информации о пользователях и их подключениях к Jira
Чтобы понимать, какой Jira-аккаунт использовать при обработке команды от каждого человека,
он получает telegram_id и ищет соответствующую запись в users.db
что хранится:
    Telegram ID пользователя.
    Jira account ID.
    Jira Cloud ID.
    Access token.
    Refresh token.
    Срок действия токенов.
    Выбранный пользователем Jira-проект.
    Данные, связанные с OAuth state.

notifications.db:
предназначена для хранения истории уведомлений о дедлайнах.

OAuth 2.0:
это протокол авторизации, который позволяет одному приложению получить разрешённый доступ к данным пользователя
в другом приложении, не запрашивая его пароль.
1. Пользователь отправляет /connect - Бот создаёт ссылку для авторизации и отправляет её пользователю.
2. Пользователь переходит по ссылке Atlassian - Он входит в свой Jira-аккаунт и разрешает приложению доступ.
3. Atlassian перенаправляет пользователя обратно - После успешной авторизации браузер переходит на адрес ATLASSIAN_REDIRECT_URI.
4. Работает твой OAuth-сервер - Он принимает callback-запрос от Atlassian. В URL передаются параметры, в частности code и state.
5. Обмен authorization code на токены - Приложение отправляет код Atlassian и получает access token и refresh token.
6. Сохранение подключения - Токены и информацию о Jira-аккаунте приложение сохраняет в users.db.
7. Пользователь может работать с Jira - Теперь бот может обращаться к Jira API от имени подключённого пользователя.

одновременно работают две части:
- Telegram-бот — принимает сообщения и команды.
- OAuth-веб-сервер — принимает HTTP-запросы от Atlassian.

Uvicorn — это ASGI-сервер, который запускает веб-приложения на Python.
само по себе объявление:
    app = FastAPI()
ещё не означает, что приложение принимает запросы из интернета. Нужно запустить сервер, который будет принимать HTTP-запросы и передавать их приложению.
Эту задачу выполняет Uvicorn. В проекте Uvicorn запускает OAuth-сервер на порту 8000
А ngrok создаёт публичный адрес, который направляет запросы на этот локальный порт.

Atlassian (Отправляет OAuth callback) -> Публичный URL ngrok (Перенаправляет запрос на localhost:8000) ->
Uvicorn (Принимает HTTP-запрос) -> oauth_app (Обрабатывает OAuth callback)
