# **Jira Bot: Telegram-бот для управления задачами и контроля дедлайнов | Python + Jira API**

## Обзор
Telegram-бот для быстрого управления задачами в Jira прямо с телефона. Позволяет просматривать задачи, создавать новые, менять их статусы и отслеживать приближающиеся дедлайны, не переключаясь постоянно между приложениями.

## Что умеет бот: 
| Команда          | Описание                      |
|------------------|-------------------------------|
| `/start`         | Запуск бота                   |
| `/help`          | Список доступных команд       |
| `/connect`       | Подключение аккаунта Jira     |
| `/jira_status`   | Проверка подключения Jira     |
| `/projects`      | Выбор проекта                 |

| `/change_status` | Изменение статуса задачи      |

## Архитектура и технологии
Стек: Python, Jira Cloud REST API, Atlassian OAuth 2.0, FastAPI, ngrok, HTTPX, SQLite

Проект построен на Python и объединяет Telegram-бота с Jira Cloud через REST API, подключение личных аккаунтов пользователей через Atlassian OAuth 2.0, обработка запросов после авторизации – FastAPI, использование ngrok для предоставления внешнего доступа к локальному серверу, отправка HTTP-запросов – HTTPX, хранение данных пользователей – SQLite

**Подробнее о том, как реализована авторизация:** авторизация реализована через интеграцию с Atlassian через OAuth 2.0. Так каждый пользователь может подключить свой Jira-аккаунт. Для обработки OAuth callback разработан отдельный сервер на FastAPI. При локальной разработке внешний доступ к нему обеспечивается через ngrok. 

**О взаимодействии с Jira:** все основные запросы к Jira API вынесены в отдельный модуль. Он отвечает за авторизацию запросов, получение данных и выполнение операций с задачами. Для каждого пользователя используются его собственные токены и выбранный проект.

**О хранении данных:** для хранения данных используется SQLite. Данные хранятся в файле `users.db` содержит информацию о пользователях, подключённых Jira-аккаунтах, токенах и выбранных проектах; `notifications.db` используется для хранения истории уведомлений о дедлайнах. 

## Структура репозитория
```text
jira_task_assistant/
│
├── bot/
│   ├── __init__.py
│   ├── handlers.py
│   ├── main.py
│   └── oauth_server.py
│
├── service/
│   ├── __init__.py
│   ├── auth_service.py
│   ├── deadline_monitor.py
│   ├── jira_client.py
│   ├── notification_store.py
│   └── user_store.py
│
├── config.py
├── .env.example
├── requirements.txt
├── users.db
└── notifications.db
```
Все основные настройки и данные для подключения к внешним сервисам вынесены в переменные и описаны в .env.example. В них входят токен Telegram-бота, параметры Atlassian OAuth и ключ шифрования токенов. Для запуска проекта необходимо создать собственный файл .env и заполнить его своими значениями.

## Назначение основных файлов
| Файл                    | Назначение                                                                     |
| ----------------------- | ------------------------------------------------------------------------------ |
| `main.py`               | Запускает Telegram-бота и OAuth-сервер                                         |
| `handlers.py`           | Обрабатывает команды бота                                                      |
| `oauth_server.py`       | Принимает OAuth callback от Atlassian                                          |
| `auth_service.py`       | Формирует ссылку авторизации, обменивает код на токены и завершает подключение |
| `jira_client.py`        | Выполняет запросы к Jira API                                                   |
| `user_store.py`         | Сохраняет данные пользователей и токены                                        |
| `deadline_monitor.py`   | Проверяет дедлайны и запускает отправку уведомлений                            |
| `notification_store.py` | Сохраняет историю уведомлений                                                  |
| `config.py`             | Загружает настройки приложения                                                 |
| `.env`                  | Содержит секретные данные и параметры подключения                              |
| `requirements.txt`      | Содержит список библиотек, необходимых для запуска проекта                     |

## Как развернуть приложение у себя
### Склонировать репозиторий
```bash
git clone <repository-url>
cd jira_task_assistant
```
### Установить зависимости
```bash
pip install -r requirements.txt
```
### Настроить переменные окружения
Создать файл .env и указать в нём следующие значения:
```bash
TELEGRAM_BOT_TOKEN=
ATLASSIAN_CLIENT_ID=
ATLASSIAN_CLIENT_SECRET=
ATLASSIAN_REDIRECT_URI=
TOKEN_ENCRYPTION_KEY=
```
### Запустить ngrok
```bash
ngrok http 8000
```
### Запустить бота
```bash
python -m bot.main
```
## Ответы на вопросы
<details>
<summary><b>Как появилась идея бота?</b></summary>
Я использую Jira в своей жизни для отслеживания задач и часто сталкиваюсь с ситуацией, когда нужно создать новую задачу, просмотреть дедлайн, изменить ее статус, а заходить для этого в приложение неудобно. Поэтому захотелось создать Telegram-бот, который позволит не тратить много времени на такое простое действие.
</details>

<details>
<summary><b>Почему именно такой набор инструментов?</b></summary>
Python удобен для разработки и также много библиотек для работы с API; SQLite удобен при разработке на Python, подходит для хранения данных небольшого приложения; с aiogram удобно разделять логику через Router.
</details>

<details>
<summary><b>Как можно использовать бот в команде?</b></summary>
Бот можно подключить в групповой чат проекта. Он будет каждое утро присылать сводку по состояниям задач, участники смогут легко следить за задачами и их статусами и делайнами.
</details>

<details>
<summary><b>Как можно масштабировать приложение?</b></summary>
Первое, что нужно сделать при масштабировании – замена SQLite на PostgreSQL. PostgreSQL обеспечит лучшую производительность при высокой нагрузке и большом числе пользователей.
  
Также в дальнейшем можно использовать Docker, чтобы бот работал постоянно, без необходимости запускать его на личном компьютере (перенести на VPS), а вместо ngrok настроить постоянный адрес сайта и защищённое HTTPS-соединение
</details>
